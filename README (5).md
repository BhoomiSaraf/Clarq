# KLA PS1 — AI-Based Restoration of Degraded Semiconductor Images

## Overview

This repository contains the final KLA PS1 solution for AI-based restoration of degraded semiconductor inspection images.

The final submitted model is **NAFNetSR + High-Frequency Loss**. It restores grayscale low-resolution `.npy` inputs to the required high-resolution outputs.

The benchmark degradation mechanisms are additive Gaussian noise, speckle noise, and downsampling.

## Final Model

### NAFNetSR + High-Frequency Loss

The model is a NAFNet-style encoder-decoder adapted for 2× super-resolution.

Its reconstruction strategy is residual:

```text
NoisyLR
   ├──────────────► Bicubic ×2 ──────────────┐
   │                                         │
   └──► NAFNet encoder/decoder ─► residual ──┤
                                             ▼
                                  Bicubic + residual
                                             │
                                             ▼
                                      Restored image
```

The architecture uses:

- grayscale input/output (`1` channel)
- feature width `32`
- encoder blocks `(2, 2, 4)`
- `4` middle NAFBlocks
- decoder blocks `(2, 2, 2)`
- convolutional downsampling
- PixelShuffle upsampling
- encoder/decoder skip connections
- a final 2× PixelShuffle reconstruction stage
- residual prediction added to bicubic ×2

The exact architecture is stored in:

```text
models/nafnet_architecture.py
```

The final weights are:

```text
models/nafnet_hf_final_checkpoint.pth
```

## High-Frequency Loss

The final training objective is:

```text
Total Loss = L1 reconstruction loss + 0.05 × High-Frequency L1 loss
```

```python
HF_WEIGHT = 0.05
loss = l1_loss + HF_WEIGHT * hf_loss
```

The high-frequency loss compares high-frequency maps of the prediction and ground truth. It is used during training to discourage excessive smoothing and preserve fine image structure.

The high-frequency loss is **not required during inference**.

## Training Data and Synthetic Degradation

Training uses paired official GT/NoisyLR data and an additional synthetic degradation pipeline generated from GT images.

The synthetic pipeline models the official degradation mechanisms:

```text
GT
 │
 ├─ 2× downsampling
 ├─ speckle noise
 └─ additive Gaussian noise
        │
        ▼
  Synthetic NoisyLR
```

The calibrated synthetic parameters in the final training notebook are:

```text
Gaussian sigma = 0.024346
Speckle sigma  = 0.167811
Downsampling   = bicubic
```

The training dataset is configured with synthetic degradation enabled. Validation uses the real paired NoisyLR images.

The notebook also performs filename/shape/range checks and verifies that the train/validation filenames do not overlap.

### Files

**`run.py`**  
Standalone inference/evaluation entry point. It accepts an input directory and output directory, loads the final checkpoint, restores every `.npy` input, and writes a corresponding `.npy` output without requiring source-code edits.

**`models/nafnet_architecture.py`**  
Exact `NAFNetSR` implementation used by the submitted checkpoint.

**`models/nafnet_hf_final_checkpoint.pth`**  
Final trained NAFNetSR + High-Frequency Loss checkpoint.

**`training/training.ipynb`**  
Reproducible training notebook containing data inspection, pairing, splitting, degradation analysis, synthetic degradation generation, model definition, training, validation, checkpoint selection and final checkpoint verification.

**`restored_test_outputs/npy/`**  
The 400 actual restored `.npy` predictions generated by the final submitted model.

**`restored_test_outputs/png/`**  
400 visual PNG representations of the restored test predictions for qualitative inspection.

**`requirements.txt`**  
Environment dependencies used by the final submission.

## Inference

The evaluator should run:

```bash
python run.py <input-dir> <output-dir>
```

Example:

```bash
python run.py ./Test_NoisyLR ./restored_output
```

`run.py`:

1. reads every `.npy` file in the input directory
2. creates the output directory if needed
3. loads the supplied final model
4. performs restoration
5. produces one `.npy` output per input
6. preserves the input filename
7. writes grayscale arrays at the target resolution
8. ensures valid finite output values in `[0,1]`

No notebook execution, manual path editing, API key, model download or user interaction is required.

## Development Workflow

The solution followed the KLA student workflow:

1. inspect GT/NoisyLR pairs and value ranges
2. verify pairing and image shapes
3. establish a simple/bicubic baseline
4. analyze the observed degradation
5. create calibrated synthetic degraded pairs
6. maintain a leakage-free validation split
7. evaluate model/loss choices
8. inspect restored images as well as numerical metrics
9. select the final NAFNetSR + High-Frequency Loss model
10. generate the final test predictions
11. validate the packaged inference script
12. verify the checkpoint and output contract

## Metrics

The development workflow uses:

- PSNR
- SSIM
- L1 reconstruction error
- high-frequency/detail diagnostics
